## Storyline / argument pattern
- **Persona hook first:** opens on a specific person ("Raka, a Semarang student, is asked by classmates which phone to buy") before any macro data. The persona recurs through the journey, funnel, before/after and UI examples.
- **Situation → Problem → Result → Strategic gap → Objective → Key questions.** This is SCQ: each problem is tagged KQ1/KQ2/KQ3, and each KQ already contains its answer direction ("→ Be the safest place to recommend and earn").
- **Reframe the battlefield:** "Copying TikTok's algorithm is costly; Blibli must win on trust and its ecosystem." The insight is framed as choosing an arena: planned purchases × dark social × Tier-2/3.
- **Branded acronym solution:** **TRUST!** = **T**ier-2/3 City Curators, **R**ewarding Daily Missions, **U**nified Ecosystem Link, **S**afe-to-Share Promise, **T**op Curator Club. The acronym spells the core insight (trust), and each letter maps to one funnel role (Acquire → Activate → Monetize → Protect → Retain), one KQ, one KPI and one budget line. The audience is rebranded too: creators become "curators".
- **Close with an ask:** "Approve Rp30B; release Rp6B for a Q1 pilot in 3 cities, gated at month 3." This is phrased as a board decision.
- **Traceability:** every main-slide claim cites an appendix ID (e.g. "details A16–A22"), so the appendix works as a defence library for Q&A.

## Frameworks & analyses used
SCQ / key questions; issue tree (4 issues / 8 root causes); SWOT → **TOWS** (each move owned by a pillar); competitor affiliate benchmark; "three engines" market map; STP via where-to-play / how-to-win / what-we-won't-do; 4 data-light personas (labelled hypotheses); creator journey map; behavioural-economics triggers (loss aversion, goal-gradient, status/social proof, belonging, certainty); creator **funnel (AARRR-style: acquire, activate, monetize, protect, retain)** with cohort math; gamification design (XP, streaks, levels, leaderboard); content playbook (channel role × format × frequency × weekly calendar); tier/loyalty programme; defensibility (copyability); Gantt + decision gates; pilot go/fix/stop; governance and decision rights; **North Star metric + KPI tree**; risk register + L×I matrix + trade-offs; financial model (ROI, payback, unit economics, break-even GMV, cost per funnel stage); 4×4 sensitivity; assumptions register; budget-to-outcome cost-per-result.

## How numbers are handled
- **Market context:** sourced stats (APJII 235M online, Nielsen 88% trust peers, HubSpot nano 8.5% engagement, Momentum Works/Magpie IQ TikTok Shop share 23→32%, US$13.1B GMV, Mordor Tier-2/3 40→50%, Bisnis.com Blibli revenue Rp22.36T and 8.5% take rate). Casebook-cited data is labelled "via MCC Casebook".
- **No TAM/SAM/SOM.** Sizing is bottom-up from the funnel: 168K sign-ups → 117.6K first shares → 84K earners → 60K active curators.
- **Financial model is simple and transparent:** active curators (+5K/month, linear) × Rp2M GMV/month × 8.5% take rate. That gives 390K curator-months → Rp780B GMV → Rp66.3B revenue; ROI = (66.3−30)/30 = 121%; payback in month 8. I spot-checked the arithmetic and it is internally consistent.
- **Budget:** Rp30B split 4 ways (40/25/20/15), then re-cut by pillar, then by line item with explicit drivers (e.g. "378 workshops × Rp5M"). 47% is variable (paid only on completed orders), 20% one-off build and 33% operating. Release is tranched per quarter (6/9/8/7).
- **Unit economics:** Rp170K revenue vs Rp77K cost per curator-month; Rp500K cost per active curator; break-even GMV Rp905K/curator/month.
- **Sensitivity:** 4×4 heatmap (growth 3–6K/month × GMV Rp1–2.5M) showing ROI and payback month, base case highlighted in red and below-break-even cells greyed. Also a conservative case (GMV halves → ROI 11%, payback M12).
- **Honesty labelling throughout:** footers mark which figures are "proposed", "planning assumptions" or "analysis"; there is a limitations box (linear growth, no churn, group-average take rate) and an assumptions register with a "how we test it / when" column.
- KPIs have Q2 and Q4 targets, a measurement source, a review cadence, an owner and a corrective action.

## Strengths
- Very tight logic chain: KQ → root cause → pillar → KPI → budget → appendix proof, with each link explicit. The casebook-mapping slide (A2) shows judges that every requirement is answered.
- The acronym is meaningful (TRUST = the insight), and each letter equals one funnel stage, so it is memorable and structural at the same time.
- A persona-led narrative (Raka) humanises a B2B-ish platform problem.
- Explicit **strategic choice and "what we will NOT do"**, which demonstrates focus.
- Financial rigour well above typical student decks: driver-based costs, unit economics, break-even, a 4×4 sensitivity, an assumptions register, tranche release, pay-for-results.
- Execution realism: 3-city pilot, go/fix/stop gates, owners and decision rights, early-warning signals, backup plans.
- Consistent labelling of assumptions vs sourced facts builds credibility.

## Weaknesses / what a judge would criticize
- **ROI is computed on Blibli revenue (GMV × take rate), not contribution.** Merchant/fulfilment costs and the existing regular commission are excluded ("outside budget"), so 121% ROI overstates the profit return. The deck admits the take rate is a group average.
- Linear growth with **no churn modelled**, and a Rp2M GMV/curator/month assumption with no benchmark (flagged as untested).
- Personas are hypotheses with no primary research (survey/interview) behind them.
- Main slides are extremely dense, hard to read when projected and reliant on the appendix. The 41-page appendix may exceed what judges read.
- Only 3 of 6 risks appear on the main slide. Brand-safety and regulatory points (affiliate disclosure, data use of KTP) are not discussed.
- Limited competitor-response analysis beyond "copyability".

## Reusable patterns
- **Cover:** a big two-line benefit headline with the second line in the accent colour ("TURNING SHOPPERS INTO / TRUSTED CURATORS"), plus a 3–4 word tagline, host/sponsor logos and team headshots.
- **Persona hook in the first 2 lines** of the problem slide, then re-use the same persona in the journey, funnel, before/after and UI examples.
- **Tag every problem with KQ1/KQ2/KQ3** and show "→ answer direction" under each KQ on the problem slide.
- **Acronym that spells the insight** (TRUST!), with one letter = one funnel role = one KPI = one budget line, shown in a single master table.
- **Letter badges + pillar colour gradient** reused across the Gantt, budget bars and tables, so judges can track pillars visually.
- **"Three engines / arenas" market map** to position the client in an uncontested space.
- **Where to play / How to win / What we will NOT do** slide.
- **Casebook-mapping slide:** each guideline → our answer → proof slide ID.
- **Funnel + "per 1,000 sign-ups" cohort walk,** showing why each drop happens and which feature fixes it.
- **KPI table columns:** Pillar · KPI · Q2 · Q4 · How measured · Review cadence · Owner · If missed.
- **Risk table columns:** Risk · Why · Early-warning signal · Mitigation · Backup · Owner, plus an L×I matrix and an explicit trade-offs box.
- **Financial pack:** summary tiles → cost by pillar → driver-based lines → quarterly phasing → monthly build → unit economics → sensitivity heatmap → assumptions register → budget-to-outcome (cost per result).
- **Footer conventions:** source line on every slide, plus a "= proposed / = planning assumption / = analysis" tag. Use section nav tabs (ANALYSIS · STRATEGY · EXECUTION · APPENDIX) and appendix IDs (A1…A41) cross-referenced from the main slides.
- **End with "Our ask"**: the amount, the tranche and the gate date.
